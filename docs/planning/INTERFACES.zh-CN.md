# ROS 与安全接口设计

机器可读草案：interfaces/ros_contract.json。
消息草案：src/fly_interfaces/msg/。
它们不是当前在线 ROS 图，也未生成消息二进制。

## 1. 数据链

主感觉输入使用 RGB Image 与对应 CameraInfo。
确认 encoding、stride、尺寸、视场、内参和源戳。
相机到车体的外参不是 CameraInfo 自动提供的。

深度用于独立的安全净空，
不默认进入果蝇网络或替它做路径规划。
必须核对单位、RGB 配准、无效像素及近地盲区。
缺失深度不能当作无障碍。

输入保留 source_sequence 与原始 source_stamp。
电脑接收到旧图像时不重新标记为新鲜画面。
相机采样率、处理率、模型步进率和底盘控制率分开。

## 2. 神经意图

NeuralIntent.msg 草案定义：

- 会话 ID 与严格递增的意图序号。
- 所依赖的图像序号及源时间。
- 原始源时钟、生产时钟及映射证书 ID。
- 有效时长，不能覆盖较早的源龄截止。
- forward_m_s 与 yaw_rad_s，使用 SI 单位。
- 模型及读出映射身份。
- 脑健康标志，仅供审查，不构成运动授权。

不同主机单调时钟不能直接相减。
时间映射必须有绑定的时钟域、误差界和有效期。
valid_for 不是“收到消息后再续满一次”的许可。
重复、乱序、旧会话、过期或未来时间异常均拒绝。

模型中途卡死、发出 NaN／Inf、图像断流或失去
时钟映射时，本机保护器关闭运动意图入口。
恢复输入不自动解除故障；由审定的重新准入处理。

## 3. 最终控制

果蝇应用不得直接发布 /diablo/MotionCmd。
仅本机已经验证的安全所有者发布最终命令，
并沿用唯一底盘驱动／SDK 所有者。
这是仍然通过 ROS 控制硬件，不是改写驱动。

MotionCtrl 的 forward、left 与模式有关。
left 不得未经核对映射为横向平移，
yaw 的正负号、单位及模式须在静态／受限验证中确认。
当前不提供可执行发布示例，防止误启动。

安全层的覆盖范围应包括：
源龄、短租约、限幅、变化率、机体故障、
人工接管、独立障碍否决以及边界约束。
它不能代为计算探索路径。

公开参考控制节点会重发缓存并自动申请控制。
所以“上层不再发消息”不等于“底盘停止”。
必须沿用或实现审定的最终执行端截止，
不以新 ROS 节点的 watchdog 替代物理停车验证。

EmergencyBrake 可能关闭腿电机，不是普通速度归零。
本工程不将它写成默认退出动作。

## 4. 默认关闭

当前 preparation.json 将以下全部关闭：
ROS 发现／发布、相机、底盘、模型执行、运动、
依赖安装及后台服务。
控制 topic 未绑定，速度和角速度限制均为零。

preflight.py 是静态文件检查器，
即使传 --real 也只退出拒绝，不加载 ROS 或硬件库。
把配置布尔量改成 true 也不会生成运行实现。

## 5. 待实现验证

消息定义可以单独编译，但本轮没有 colcon 构建。
下一阶段先用独立 ROS 命名空间做合成收发，
不连接真实 MotionCmd 或开启设备。

之后才建立相机影子模式和最终保护适配。
影子模式不得创建真实底盘命令发布者；
应独立记录 shadow_intent，不能靠发送零速度冒充只读。
