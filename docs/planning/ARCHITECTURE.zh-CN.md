# 工程架构

日期：2026-09-22。
目标：果蝇连接组网络接收刑天视觉输入，
输出身体运动意图，实现无指定目标的自由探索。
所有应用层硬件输入输出通过 ROS。
本轮仅工程准备，不启动实际链路。

## 1. 系统职责

```text
机器人／Foxy                    电脑／脑运行时
相机ROS图像 ──版本兼容传输──→ 视网膜编码
                                      ↓
                           持续状态的连接组网络
                                      ↓
                           下降神经元群动作读出
                                      ↓
本机安全网关 ←──限时意图──── 运动意图ROS适配
      ↓
受保护的唯一ROS底盘控制端
      ↓
原厂平衡、轮腿协调、电机执行
      ↓
环境与摄像头视野发生变化
```

保留已有硬件驱动及唯一硬件所有者。
不得启动另一个底盘节点争抢控制权或串口。
本项目不重写 USB、UART、SDK 或电机驱动。
不把“接收 ROS 话题”误称为已完成安全控制。

首期固定身体模式，仅前进、转向和受控停止。
果蝇网络不负责双轮动态平衡或关节级力矩。
最终车体模式及限速沿用既有审定范围；
不因新建工程而开放跳跃、站立或升降。

## 2. 实测计算资源

2026-09-22 本轮只读清点：

- 机器人：aarch64，4 核，物理内存约 1.75 GiB。
- 系统：Ubuntu 20.04，Python 3.8.10，Foxy。
- 当时 home 所在文件系统空闲约 15.18 GiB。
- Orbbec 包元数据版本：1.5.11。
- DIABLO 控制及消息包元数据版本：1.0.0。
- 电脑：RTX 4060 Laptop，显存 8188 MiB。
- 电脑驱动版本：566.07。

版本来自包元数据，不保证实际加载的库完全同版。
SSH 非交互环境未 source ROS，因此命令查找中的
ros2=null 不代表 Foxy 未安装。
同理，Python 分发元数据未找到 rclpy／opencv，
不能直接断言 ROS 或 apt 提供的模块不存在。

将完整脑模型放到现有电脑先行验证。
不在约 2 GB 的机器人上安装完整深度学习环境。
8 GB 显存是否满足所选完整图及持续模拟，
由首阶段测量决定，当前不能承诺实时。

## 4. 脑运行时与接口

模型只初始化一次，保留膜电位、突触状态、
延迟队列、随机数状态及必要的内部状态。
禁止每帧重新初始化或重启离线 benchmark。

建议内部接口：

```text
load_graph(manifest) → graph_identity
initialize(seed, parameters) → persistent_state
encode_frame(frame, calibration) → sensory_drive
advance(state, drive, duration) → state, neural_readout
decode(readout, fixed_mapping) → motion_intent
snapshot() → bounded diagnostic state
```

Eon PyTorch 源码已有 state_init/forward 分解，
便于包装持续状态；其主要入口仍是 benchmark，
本项目仍须开发在线调度与时效处理。

参考模型 dt=0.1 ms，每模拟 1 秒需 10000 次步进。
这是源模型数值设置，不是 ROS 发布频率。
拟先以 10 Hz 视觉行为循环做资源评估，
再检查 20 Hz 是否必要；均为设计目标。
不为追求速度擅自增大 dt 后仍宣称模型等价。

读取少量神经群统计，不逐步向 ROS 广播全脑状态。
神经活动到运动使用固定、可追溯的低维读出。
前进与转向可由归一化活动及左右差异生成，
具体细胞、系数、滤波窗口在开发集确定并冻结。

## 5. ROS 与跨版本边界

机器人 Foxy／Python 3.8 保持不变。
电脑既有 Jazzy 环境不能默认与 Foxy 原生互通。

推荐把硬件通信段固定为版本兼容的 ROS 段，
脑运行时使用单独 Python 环境，
二者通过有界本地 IPC 交换图像刺激和神经意图。
若无法构建同发行版端点，再采用明确的受限桥。
桥接方式是实现决策，不在本轮安装或更改系统。

FlyVis 当前声明 Python >=3.9,<3.13；
其 pretrained 额外依赖还包含旧版本约束。
因此即使电脑 Python 3.12 满足主包范围，
也不等于预训练资产的依赖组合已经可用。
先验证资产与锁定环境，不升级机器人 Python。

采用最新帧槽、有限队列、原始源戳及序号。
无线图像优先减少分辨率／帧率或使用图像压缩，
压缩失真与时延需要联合评价。
仅发送任务实际需要的数据；
安全深度／雷达尽量留在机器人本机。

不把 reliable QoS、NTP 或 topic 存在当作时效证明。
具体时间证书、租约和保护上限沿用审定保护器，
无法满足时停止，不通过放宽门槛使测试通过。

## 6. 不可被替代的行为因果链

路径选择来自神经网络，不来自隐藏的 A*／Nav2。
外部 SLAM 或轨迹跟踪仅用于评价与边界监护，
不向神经网络偷偷注入完整导航解。

安全层只有 veto、限幅及停车权，
记录网络原始意图、否决原因、最终执行三条日志。
不能因安全层避免碰撞就宣称果蝇学会避障。

禁止用随机转向脚本替代神经网络探索。
背景驱动、内部状态或可塑性属于显式模型定义，
须单独记录并做消融，而非隐藏补丁。

## 7. 现在已有的问题如何处理

既有项目最新 STATE 与本地 HANDOFF 一致：
相机静态尝试以日志分类故障停止，实际 ROS 帧为零。
这不是本轮再次启动得到的结果，也不能视为硬件损坏。
相关分类器修复由原项目版本化处理，
新项目不覆盖旧锁、不盲跑旧启动入口。

已有相机、时效传输与受保护执行器可复用；
它们的集成及物理资格仍是后续关键依赖。
所谓“不接线”只省去重建硬件驱动，
不会自动消除这些软件接口和实机验证工作。

本轮旧项目 STATE、BLOCKERS、mission 配置及
指定包元数据记录身份，交付后再检查是否一致。
该核对只覆盖明确列出的文件，不代表全盘未变。
