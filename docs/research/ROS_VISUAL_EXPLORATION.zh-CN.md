# 果蝇神经网络驱动刑天视觉探索

日期：2026-09-22。
类型：用户需求收敛与架构设计，非实机执行。

## 1. 用户明确的目标

用户要求：

> 需要做的是让果蝇的神经网络接入刑天的视觉信号、
> 控制轮腿自由探索、所有硬件控制直接调用ros话题

据此，将目标收敛为：
摄像头输入改变果蝇神经网络状态，
神经活动决定刑天运动，运动再改变视觉输入。

这是神经网络参与的真实感觉—行动闭环，
不是由 Nav2、A* 或人工巡航脚本决定路线，
再用果蝇模型充当可视化或无效中间层。

本文件优先于初始调研中尚未确定的任务选择。
FEASIBILITY.zh-CN.md 中的证据及接口风险仍适用。

## 2. 明确的实现边界

- 应用层的所有硬件输入输出使用 ROS 接口。
- 复用相机与底盘 ROS 驱动，不另写 USB／UART。
- 硬件驱动内部仍负责 SDK／总线通信，无法消除。
- 果蝇网络负责行为方向和速度意图。
- 原有底盘控制器继续负责平衡与轮腿协调。
- 首期固定身体模式，不让网络自动跳跃或升降。
- 安全层只能限幅、否决或受控停止，不能代为寻路。
- 完整网络或子网络的最终范围尚需确定。
- 默认优先考察完整连接组；不得暗中裁剪或
  改用普通神经网络后仍宣称完整果蝇脑控制。

“通过 ROS 控制轮腿”在首期指发送身体运动命令，
不是让神经网络分别输出所有关节的力矩。
若用户需要后者，应另立低层运动控制研究范围。

## 3. ROS 系统结构

```text
现有摄像头 ROS 驱动
  │ Image + CameraInfo + 原始时间
  ▼
fly_visual_encoder
  │ 视野映射、亮度／运动刺激编码
  ▼
fly_brain
  │ 持续神经状态、真实连接组传播
  ▼
fly_motor_readout
  │ 线速度／转向意图，含时间与有效期
  ▼
本机独立 safety_gateway
  │ 唯一控制发布者；不做目标规划
  ▼
现有、经保护的 DIABLO ROS 控制端
  │ /diablo/MotionCmd
  ▼
原厂轮腿控制器 → 真实运动 → 下一帧视觉
```

深度、IMU、轮反馈与遥控状态供安全网关使用。
如后续给神经网络加入本体反馈，应单独明确编码，
不能将所有遥测随意注入不对应的神经元。

拟议 /fly/* 名称是新接口设计，
不是已经存在或验证过的 ROS 图。

## 4. 输入输出契约

| 用途 | 文档接口／拟议接口 | 处理方式 |
| --- | --- | --- |
| 视觉主输入 | /camera/color/image_raw | 订阅 Image，保留源戳 |
| 相机投影 | /camera/color/camera_info | 校验 CameraInfo 与帧对应 |
| 安全距离 | /camera/depth/image_raw | 核对单位、对齐与近地盲区 |
| 机体状态 | /diablo/sensor/Imu、Motors、Body_state | 源龄校验，不能仅依赖接收时刻 |
| 神经状态摘要 | 拟议 /fly/neural_state | 发布选定活动摘要，不必全脑逐步广播 |
| 运动意图 | 拟议 /fly/command_intent | 明确线速度、角速度、序号、有效期 |
| 最终底盘命令 | /diablo/MotionCmd | 仅安全网关有发布权 |

相机命名空间可能重映射；
文档接口不等于当前机器已经在发布这些话题。
MotionCtrl 不是标准 Twist。
其 forward、left 等字段须按实际模式解释。

ROS graph 可能发现同名但属于其他设备的端点。
必须绑定本车驱动来源、域、命名空间和发布者，
不能把共享网络上的 /cmd_vel 当作刑天控制接口。

## 5. 视觉到神经网络：主要研发点

### 5.1 为什么不直接把 RGB 数组送进全脑

LIF 连接组模型接收神经刺激，不直接接收图像语义。
需要把相机视野转换成视网膜位置对应的刺激，
并标定采样、亮度、对比度、时间和输入幅度。

单目前视摄像头不能自动等价于果蝇的大范围复眼。
首期明确真实可见视域，不将缺失视域伪造为观察。

### 5.2 两条视觉实现路线

路线 A：真实连接组模型的视觉输入通路。
利用已选数据集的感觉神经元注释及空间映射，
把视觉刺激输入其视觉系统，再读出下降信号。
优点是可以维持同一图中的传播边界。
难点是完整、可靠的视网膜位置及动态参数映射。

路线 B：FlyVis 作为视觉前端，加全脑模型。
FlyVis 是 Lappalainen 等人 2024 年 Nature
论文的官方实现，提供果蝇视觉系统模型与预训练接口。
它是连接组约束、任务优化的视觉模型，
不是直接获得完整果蝇脑的生物参数。

跨模型拼接必须明确细胞类型、左右侧、空间位置、
活动量纲及速率到尖峰转换。
不能把 FlyWire 的神经元 ID 直接套给 MaleCNS，
也不能同时重复运行两套重叠视觉网络却不说明。

选择哪一条需要接口验证，而不是默认下载就互通。
FlyVis 官方实现：
https://github.com/TuragaLab/flyvis

### 5.3 视觉有效性必须可测

同一神经初态下比较真实帧、冻结帧、打乱帧，
以及遮断选定视觉通路后的输出。
如果运动主要不随视觉改变，
就不能称为视觉驱动探索。

Eon 3 月技术说明明确披露当时视觉对演示行为
影响有限，因此不能把该演示作为本目标已解决的证据。

## 6. 自由探索不等于神经网络随机发放

定义首期探索为：没有人工路径或指定终点，
网络持续生成运动意图，且根据视野变化调整行为。
这并不自动意味着最优覆盖、记忆或学习。

原始 Shiu 模型以零基线发放为重要设定。
固定连接组可能静默、饱和或陷入单一行为，
不能保证一接摄像头就自然产生丰富探索。

如需背景驱动、内在状态或可塑性，
必须明确模型修改、作用位置和标定方法。
不能用随机转向脚本掩盖神经网络没有动作输出，
也不能把外加奖励规则称为原生果蝇学习能力。

运动读出可以从选定下降神经元群活动计算
前向意图与左右转向差异，
再进行有界滤波和幅度限制。
选定细胞功能及读取方式需依数据集核对。

## 8. 部署建议

第一版神经网络放在现有电脑／工作站，
机器人保留相机、底盘 ROS 节点及本机安全网关。
这是 ROS 分布式架构，不需要先增加机载 GPU。

是否最终将模型放到机器人机载计算机，
由完整网络的墙钟吞吐、内存、功耗和延迟决定。
不把 GPU 后端存在等同于实时性能达标。

建议视觉行为层先以约 10–20 Hz 为工程目标，
这不是厂商控制频率，也不是已经实测的能力。
神经模型内部时间步、ROS 输出频率及
原厂平衡控制频率必须区分。

安全网关独立于神经模型和电脑网络连接。
上游图像或意图过期时阻止继续执行旧动作，
按照已验证的底盘停止机制保持可控状态。
故障后不得因新消息到来自动恢复运动。

公开原版 ROS 控制节点存在缓存命令重发逻辑；
只停止发布上层话题不能视为停车证明。

## 9. 实现顺序与判据

1. 离线视觉编码与神经响应。
   先证明动态画面能够影响网络和动作读出。
2. 机器人仿真探索。
   测试无目标运动、视觉依赖、延迟及卡死行为。
3. ROS 影子运行。
   接真实输入，仅记录动作意图，不发布运动。
4. 本机安全网关与故障注入。
   验证旧命令、断链、重复消息、退出与人工接管。
5. 独立实机准入后低速探索。
   固定身体模式，保留干预与失败记录。

核心评价是视觉因果作用、运动有效性、
单位时间覆盖／重复访问、安全干预率和时延。
可用外部定位或 SLAM 离线评价轨迹，
但首期不让它成为驱动机器人的隐藏导航器。

本文件不是正式实验协议；
没有锁定场景、种子、预算或性能门槛。
