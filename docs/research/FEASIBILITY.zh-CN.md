# 果蝇连接组控制刑天轮腿机器人：可行性调研

调研日期：2026-09-22。
对象暂按直驱科技 DIABLO／刑天理解。
如果用户指另一款机器人，接口结论需另核对。

## 1. 结论

可以做，但应把果蝇神经网络作为行为决策层，
而不是替代刑天的平衡、轮腿协调和电机控制。

实现“真实连接组参与感知—行动闭环”的演示，
工程难度中等，具有明确的开源起点。
实现全脑在线运行并可靠适配真实环境，难度较高。
让果蝇网络直接控制轮腿电机，不是现成移植任务。

“装上”可以指三个不同层次：

| 目标 | 判断 | 推荐程度 |
| --- | --- | --- |
| 果蝇回路输出前进、转向、停止 | 中等难度，可作为首期目标 | 高 |
| 全连接组参与实时感知—运动闭环 | 较难，需要计算与接口验证 | 第二阶段 |
| 取代原厂平衡、直接输出电机力矩 | 很难，身体动力学完全不同 | 不宜起步 |
| 自动获得更强导航、学习、越障能力 | 现有证据不足以保证 | 不作为承诺 |

## 2. 最近“果蝇大脑”具体指什么

### 2.1 2026 年 9 月的 MaleCNS 热点

Google Research 于 9 月 3 日公布：
MaleCNS 包含雄性果蝇脑及腹神经索，
超过 16.6 万个神经元、约 1.25 亿个突触连接。[S1]

Eon 9 月 11 日文章将最近的 Minecraft、Doom、
Mario 等果蝇演示与这次数据发布联系起来。[S2]
用户说的“特别火”可能指这波内容；
尚未收到用户所指视频或仓库，不能完全确认。

连接组是结构测量，不是已经训练完成的控制器。
膜电位、神经调质、突触动力学、学习状态等，
仍须通过模型假设、参数估计或实验数据补充。

生物突触接触数量、按神经元对聚合后的图边数、
经过筛选的模拟连接数不是同一个统计量。
不能直接用各仓库的数字比较模型完整程度。

### 2.2 2024 年的 FlyWire 与计算脑模型

Shiu 等人的 Nature 论文构建了 LIF 神经网络，
以连接组和预测递质类型研究取食及梳理回路。[S4]
论文实现的版本包含约 12.74 万个神经元；
更新数据版本的规模会变化，不能混用版本数字。

其主要证据是特定神经回路预测及生物实验验证，
并非通用导航、自主学习或机器人控制性能。
宣传中的约 91% 也不能解释成“恢复了 91% 智能”。

### 2.3 Eon 的虚拟具身果蝇

Eon 2026 年 3 月技术说明描述了以下组合：[S3]

1. 果蝇连接组约束的 LIF 网络。
2. 部分感觉通路的输入映射。
3. 少量下降神经元的行为读出。
4. NeuroMechFly 身体与既有底层运动控制器。

它不是全部肌肉直接由完整生物运动通路驱动。
转向采用 DNa01／DNa02 等输出，
前向速度使用 oDN1 等输出，再控制虚拟身体。
部分感觉输入和动作映射由工程人员设定。

该技术说明还指出：当时视觉活动对演示行为
尚无显著影响，视觉逃逸尚未落实到身体动作。
这些是该文描述的版本状态，不能断言所有
2026 年 9 月衍生项目仍具有完全相同的限制。

文中每 15 ms 同步脑与身体，指模拟时间步长；
这本身不是 15 ms 墙钟延迟或实时性能保证。

### 2.4 游戏演示不等于已经学会游戏

当前 DOOMFLY README 披露，其 v6 候选未通过
视觉、条件学习和生存验证，未证明学会生存。[S8]
这不否认连接组仿真的价值，但说明需要区分：
神经活动驱动按钮、工程映射、真正学习及优势。

## 3. 刑天为什么可以接，为什么不能直接换脑

公开 DIABLO ROS2 源码提供运动控制消息，
包含 forward、left、up、roll、pitch 等字段。
控制节点将这些字段交给底层 SDK。[S9–S11]
因此可以在上层加入神经模型，而保留原控制器。

公开 README 使用 /diablo/MotionCmd 及
motion_msgs/msg/MotionCtrl；
不能假设任意 /cmd_vel 已经与本机安全连接。
left 的具体角速度／模式语义须结合实际固件、
控制模式与接口测试确认，不能当作横向平移。

果蝇是六足身体，刑天是双轮腿身体。
关节数、惯量、接触方式、稳定条件和执行器不同。
即使 MaleCNS 已包括腹神经索，
也不会自然产生刑天需要的平衡力矩。

建议架构如下：

```text
摄像头／深度／距离输入
          ↓
感觉编码器（可解释、版本固定）
          ↓
果蝇连接组网络或明确标识的子回路
          ↓
下降信号读出：前进／转向／停止意图
          ↓
本机独立安全仲裁与有效期检查
          ↓
DIABLO SDK／经过验证的 ROS2 适配
          ↓
原厂平衡与轮腿控制 → 电机
          ↓
真实运动改变下一时刻的感觉输入
```

以上是建议设计，不是已经部署的系统。
裁剪子回路后，应称为“果蝇连接组子回路控制”，
不能继续宣称完整全脑运行。

## 4. 真正的四个难点

### 4.1 感觉输入如何进入神经元

摄像头图像不能不经处理就输入任意神经元。
需要确定视野映射、亮度／运动特征、刺激量纲、
发放率标定、输入延迟与饱和范围。

首期可考虑运动方向响应、迫近刺激响应，
或通过人工定义的吸引信号做目标趋近。
把视觉目标编码成“糖刺激”属于人工跨模态映射，
不是证明果蝇网络本来就能理解机器人看到的目标。

### 4.2 神经活动如何变成安全动作

少量读出信号可映射到期望线速度和转向角速度。
需要归一化、短窗统计、滤波、幅度与变化率限制。
这些都是待标定的设计，不是可直接复制的常数。

安全模块只能限幅、否决或停车，
不应暗中承担全部路径规划后把成功归因于果蝇。
应分别记录原始神经意图、干预及最终执行命令。

### 4.3 实时性与机载算力

Eon 公共仓库已有 Brian2、PyTorch、GeNN 等实现，
其 README 提供 RTX 4070 环境参考。[S6]
这证明存在桌面 GPU 实现路径，
不证明用户机载设备满足端到端实时要求。

原始论文代码偏向离线刺激与统计；
在线闭环还需持续状态、动态输入、非阻塞输出。
不应把每帧重新启动离线仿真当作实时控制。

建议先在已有工作站做离线或仿真验证，
再依据真实吞吐、内存、功耗及延迟决定机载硬件。
不要尚未测量就承诺树莓派或某款 Jetson 足够。

指标至少包含模拟时间／墙钟时间、P99 延迟、
输入时效、命令时效、丢帧、内存和连续运行稳定性。
离线可以慢于实时，实机则不能无限积压旧输入。
远程算力可用于早期研究，本机必须独立执行安全层。

### 4.4 当前公开控制节点的缓存风险

本次读取的 diablo_ctrl.cpp 中，
后台约每 180 ms 重发缓存运动命令；
回调也会直接发送，所以不是“最高只有 5.6 Hz”。
所读源码未显示上游消息新鲜度超时检查，
并存在失去控制后自动申请控制的路径。[S11]

SDK 头文件的控制超时默认值为 500 ms。[S12]
但如果后台持续发送缓存，底层仍可能收到有效包，
不能因此保证神经网络停止后机器人自动停车。
这是一项公开源码风险，不是对用户固件的实测结论。

还需注意，SDK 的 EmergencyBrake 注释明确说，
该动作会关闭腿电机并制动车轮，可能造成损伤。
不能把它当作保持平衡的普通“速度归零”。

必须复用或实现经过验证的本机安全仲裁：
命令有效期、输入时间、单一控制权、故障锁存、
禁止自动恢复运动、人工接管与障碍独立否决。
断网、模型卡死和重启恢复都要先做无运动验证。

## 5. 开源路线与选择

| 资源 | 用途 | 使用注意 |
| --- | --- | --- |
| Shiu 原始模型 [S5] | 生物模型及刺激实验起点 | 默认历史数据版本需核对 |
| Eon fly-brain [S6] | 多后端及 GPU 仿真实现参考 | 不是完整机器人部署包 |
| MaleCNS [S1] | 新的脑＋腹神经索数据源 | 不能直接套用 FlyWire 神经元 ID |
| FlyGym [S7] | 虚拟果蝇感觉与身体仿真 | 不是刑天的身体模型 |
| DIABLO ROS2 [S9–S11] | 上层运动接口与遥测 | 实机版本、时间与安全层另验 |

若优先快速做出可靠闭环，
可先用成熟 FlyWire／Shiu 工具链验证接口。
若用户明确要求最近的完整 MaleCNS，
则单独锁定 MaleCNS 数据、模型和细胞映射，
不要为了进度把旧模型冒充为新数据。

当前 FlyGym README 说明 2026 年 3 月引入
不向后兼容的 2.x API，旧版本移至另一个仓库。
README 中的身体仿真加速倍率，
不是完整果蝇脑＋刑天闭环的实测性能。[S7]

代码、数据、可视化资产的许可需分别核对。
例如 Eon 当前 README 声明 GPL-2.0-or-later，
不能把全部依赖统称为 MIT 或默认可闭源分发。

## 6. 推荐的最小项目

首期范围：平整封闭区域、低速、固定身体模式，
只允许前进、左右转向及受控停止。
不开放跳跃、自动升降或未经验证的身体模式切换。

演示目标可表述为：
“由果蝇连接组神经活动驱动刑天的感觉—行为闭环”。

建议分期如下，均不是本次已经执行的任务：

1. 离线验证网络与读出。
   确认刺激引起预期响应，并测试无输入／异常输入。
2. 在机器人运动学或动力学仿真中闭环。
   NeuroMechFly 仅用于果蝇参考，不替代机器人模型。
3. 真实传感器影子模式。
   只记录拟执行动作，不连接运动输出。
4. 安全准入后进行有人监督的低速实机演示。
   先验证停更、断链和接管，再扩大行为任务。

前提是底盘、相机、控制桥与停车机制已经合格。
在此前提下，一名熟悉 ROS 和 Python 的开发者，
离线原型可按约 1–2 周、低速实机演示约 3–6 周
总工期估算；较完整对照研究可能需要 2–3 个月以上。
这些是工程量估计，不是文献结论或交付保证。
全 MaleCNS、接口故障或机载优化可能明显延长。

用户既有 DIABLO 项目仍有独立安全与静态准入记录。
本次没有连接机器人，也不继承其他项目的运动授权。
公开接口可用不等于用户当前实机已经可运动。

## 7. 怎样判断是否值得继续

如果目标是科研、展示、探索生物回路跨身体控制，
该方向值得开展一个边界清楚的原型。

如果目标只是让刑天更快、更稳地导航和越障，
传统导航、视觉伺服和轮腿控制是更直接的基线。
连接组不是默认更高效或更鲁棒的替代品。

后续对照建议包括：

- 同输入、同动作接口的简单规则控制器。
- 真连接组与保持关键统计量的随机化连接组。
- 神经读出关闭或打乱后的控制器。
- 若研究学习，再加入预算匹配的学习基线。

各方法应共享传感器、速度范围及安全仲裁。
记录完成率、碰撞／干预、路径效率、延迟和能耗。
不得把安全层救场、脚本动作或人工选片，
当成果蝇网络自主学习或优于基线的证据。

这只是后续研究设计建议，尚无实验数据、
固定样本量、种子、执行预算或正式协议锁。
